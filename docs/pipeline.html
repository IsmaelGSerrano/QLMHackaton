Sample small labelled subgraphs

scripts/build_subgraphs.pysrc/qlmaml/subgraphs.py→ data/processed/subgraphs_HI-Small_n8.parquet

The task becomes graph classification: given a directed subgraph of at most 8 accounts (8 qubits, the hardware track), does it contain a laundering attempt? The 12-account cache is the simulator track.

Positives

  • The accounts of one attempt, as the induced subgraph over the attempt's time window, so normal transfers between those accounts are included.
  • Attempts with more than 8 accounts are cut in time: keep accounts in the order the money reaches them. 171 attempts were cut.
  • 36 positives were dropped because no 5 matching negatives existed (small, dense shapes).

Negatives, 5 per positive

  • Laundering-free, from the same split, matched on account count (exact) and gate count.
  • ego (1,399): an ego-net around a normal transfer.
  • pairs (271): unrelated normal transfers, for sparse positives such as BIPARTITE. Without them, "disconnected" would mean "laundering".

Why the cap is 8 accounts (8 qubits)

A choice for the hardware track, not a hard limit: the 12-account cache was trained on the simulator too. Eight is the trade-off between covering the attempts and keeping circuits clean on Garnet.

CZ works only between neighbouring qubits, and each SWAP costs 3 more CZ. At 8 there were enough 0-SWAP graphs for all 60 hardware test graphs and every equivariance copy. The PR-AUC rows use different test sets, and the gap is about the size of the seed-to-seed spread.

3 · The other reasons
  • Noise grows with CZ count. Each merged edge costs 2 CZ. Even at 8 qubits, Garnet's scores were 0.022 from exact on average; more gates would hide the effect being measured.
  • Room for the equivariance copies. Each test graph runs on 3 different qubit sets. With 19 usable qubits that day, an 8-account graph has many more distinct placements than a 12- or 16-account one.
  • Project rules. CLAUDE.md asks for about 4–16 qubits, shallow circuits, and a checked chip fit.

Not a simulator limit: 8 qubits is 256 amplitudes, 12 is 4,096, all 20 of Garnet about a million, all easy on a laptop. That is also why no speed advantage is possible at this size. On the slides, the cap must be stated as subsampling.

Merge transfers into gate inputs

src/qlmaml/circuit.pygraph_from_merged

Each subgraph becomes a CircuitGraph: a list of accounts with one feature each, and a list of directed edges in time order.

  • Repeated transfers from the same payer to the same payee merge into one edge: total amount in USD, count, first timestamp. One gate per pair keeps the circuit shallow.
  • Edges are ordered by first timestamp (ties: amount, then count). The order never depends on account names.
  • Node feature f_i = log(1 + total flow in and out). It has no direction on purpose, so the RZZ ablation gets no direction from features.

Build the circuit: one qubit per account, one gate per edge

src/qlmaml/circuit.pybuild_gatesstatevector_mean_zqiskit_circuit

Pick a motif and an edge gate. The builder draws the circuit and runs it with one random set of shared weights. Each motif is compared with its twin: same undirected shape, opposite direction. With RZZ the two always score the same; with ZX they differ.

Note · what a gate is

A qubit holds a state between |0⟩ and |1⟩. Measuring it gives 0 or 1 with some probability; ⟨Z⟩ = P(0) − P(1) summarises that as one number from +1 (always 0) to −1 (always 1). A gate is one operation on one or two qubits. A circuit is a list of gates applied in order, followed by measurement. Rotation gates take an angle; in this model each angle comes from the data times a trained weight.

A two-qubit gate can entangle the qubits: afterwards one qubit's result depends on the other's. That is how a transfer links the payer's and payee's qubits.

ZX gate · directed · the model

exp(−iθ Zpayer Xpayee) = cos θ · I − i sin θ · ZpayerXpayee

The payer acts as a switch and the payee gets rotated. Z on the payer only reads its state (it adds a sign); X on the payee turns it.

Payer isWhat happens to the payee
|0⟩rotates about X by +2θ
|1⟩rotates about X by −2θ
  • Direction: ZuXv and XuZv are different gates, so A → B and B → A give different circuits. Like the money, the effect goes from payer to payee.
  • Order matters: for a mule B in A → B → C, B is the X end of one gate and the Z end of the next. Those two gates do not commute, so the code applies them in timestamp order.
  • Start state: a payee in |+⟩ is unchanged by X and only puts a phase on the payer. The circuit starts in |0⟩ and applies RY first so the gate entangles.
RZZ gate · symmetric · the ablation

exp(−iθ Zu Zv) = diag(e−iθ, e+iθ, e+iθ, e−iθ)

Both ends only read their state. The gate adds a phase that depends on whether the two qubits agree.

The two qubitsPhase added
agree (|00⟩, |11⟩)e−iθ
differ (|01⟩, |10⟩)e+iθ
  • No direction: swapping the ends gives the same gate, so the circuit sees only the undirected shape. FAN-IN = FAN-OUT and CYCLE = no-return triangle for every choice of weights.
  • No order: all ZZ gates commute, so the transfer timing is lost as well.
  • Used by Skolik et al. [9] and Verdon et al. [8]. We keep it as the control: same graph, same 7 weights, only the edge gate differs.
Same cost on Garnet
ZX(θ)= Hpayee · ZZ(θ) · Hpayeeand ZZ(θ) → 2 CZ + PRX

H turns X into Z (H X H = Z), so ZX is a ZZ gate with the payee's basis changed. Both cost 2 CZ per merged edge, so the ablation compares the gates at equal hardware cost. Naming: Qiskit's RZZ(φ) is exp(−iφ/2 ZZ), so θ here is RZZ(2θ). The design decision is in docs/adr/0001-directed-edge-gates.md.

Garnet, 20 qubits, 30 couplers

Example: a 5-account FAN-OUT placed with 0 SWAPs (centre on QB10). QB14 was out of calibration on 2026-11-06.

  • Each circuit is transpiled once for IQMFakeGarnet, optimization level 3, VF2 layout first. Graphs that fit the lattice need no SWAP.
  • The 60 test graphs are picked with the test class ratio (10 positive, 50 negative), 0-SWAP graphs first. All 60 needed 0 SWAPs.
  • Equivariance check: 20 graphs × 3 relabelled copies, each copy pinned to a different set of physical qubits.
  • Live Garnet drops qubits that are out of calibration and renumbers the rest. The code maps qubits by name (QB1…QB20), not index. 35 circuits touched a missing qubit or coupler and were re-transpiled for the live chip.
  • The 7 trained weights are bound into the circuits before transpiling. Nothing is trained on hardware.

Two kinds of calibration
  • Chip calibration (IQM). Superconducting qubits drift over hours, so IQM re-tunes each qubit's frequency, the PRX and CZ pulses, and the threshold that turns the measured signal into 0 or 1. A qubit that fails is switched off and the others are renumbered: QB14 on 2026-11-06. The code maps qubits by name for this reason (stage 7).
  • Readout calibration (ours). Even a well-tuned chip misreads some results. Two extra circuits in each job measure how often each qubit is misread, so the scores can be corrected.
Why readout calibration is needed

The model's score uses ⟨Z_i⟩, which comes straight from how often qubit i reads 1. If a qubit in |0⟩ is sometimes read as 1 (rate e0) and a qubit in |1⟩ is sometimes read as 0 (rate e1), the measured value is

⟨Z⟩measured = (1 − e0 − e1) · ⟨Z⟩true + (e1 − e0)

  • It shrinks every value toward zero by the factor (1 − e0 − e1). The readout s then moves toward 0 and every score toward logistic(β₀), so positives and negatives look more alike.
  • It shifts the value by (e1 − e0). Reading |1⟩ as 0 is usually more likely, because a qubit can decay to |0⟩ during the measurement.
  • Each qubit is different. The same graph placed on other physical qubits gets a different error, which also breaks the equivariance check (stage 9).
  • The errors change with time. That is why every job carries its own calibration circuits instead of reusing old numbers.

Example only, not measured: with e0 = 2 % and e1 = 5 %, a true ⟨Z⟩ of 0.50 is read as 0.93 × 0.50 + 0.03 = 0.495, and a true −0.50 as −0.435.

How it is done (qlmaml.garnet)
  • readout_calibration_circuits: cal_zeros measures every qubit in |0⟩; cal_ones applies X to every qubit, then measures. 2,000 shots each, on all 19 live qubits.
  • readout_errors: per physical qubit, e0 = P(read 1 | prepared 0) and e1 = P(read 0 | prepared 1).
  • mitigated_mean_z: undoes the error per qubit, p = (p_raw − e0) / (1 − e0 − e1), clipped to [0, 1], then s = 1 − 2 · mean(p). It uses the qubit each account was finally measured on, after any SWAPs.
  • Two circuits are enough because the score only needs each qubit's own ⟨Z⟩, not the full 2ⁿ × 2ⁿ error table. The price: it assumes each qubit's readout error is independent of its neighbours.
  • A qubit with 1 − e0 − e1 ≤ 0 carries no information (the free mock returns random bits) and is left uncorrected.

Assumptions: the parameter-shift rule for gradients (2 extra circuits per parametrised gate, since every gate's generator has eigenvalues ±1), 2,000 shots per circuit, a graph with 8 merged edges, no queue, and the per-circuit time seen on 2026-11-06. A real run would also need the queue and calibration drift handled across days. This is why the project trains on the simulator and uses Garnet only for inference.

The comparison says nothing in favour of quantum speed at this size: 8–12 qubits fit in a laptop's memory many times over. A speed argument would need circuits too large to simulate, and this project has no evidence that such circuits would classify better.
